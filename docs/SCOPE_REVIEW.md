# 范围审视：244 条里哪些真的必须做

> 2026-11-17 · 数据脚本 `python3 scripts/scope_tiers.py`

## 1. 为什么“48.4%”让人不服

`FEATURE_MATRIX.md` 是**上游 Tabby 能力审计**：目标是“尽量全覆盖”，所以它把
Tabby 的所有能力都列成了条目，包括我们可能永远不做的（Zmodem、Node sidecar、
Angular 插件 UI、Windows 专属 shell）。直接把 244 条当分母，等于用“复刻 Tabby”
的尺子量一个终端产品，数字自然偏低。

按产品必要性重新分档后：

| 档位 | 条目 | 已实现 | 部分 | 待核实 | 未开始 | 不做 | 加权 |
|---|---|---|---|---|---|---|---|
| P0 核心终端 | 100 | 44 | 45 | 1 | 9 | 1 | **66.8%** |
| P0 基础连接 | 21 | 0 | 8 | 0 | 13 | 0 | **19.0%** |
| P1 工作区与设置 | 75 | 8 | 51 | 1 | 15 | 0 | **45.0%** |
| P2 高级连接 | 30 | 2 | 9 | 10 | 8 | 1 | 30.0% |
| P3 不建议/观察 | 18 | 3 | 2 | 2 | 6 | 5 | 25.0% |
| **全部** | **244** | 57 | 115 | 14 | 51 | 7 | 48.4% |

- **P0 合计 121 条，加权 58.5%**：核心终端已经接近“能用且好用”；
- **P0+P1 合计 196 条（占 80%），加权 53.3%**；
- 真正的短板是 **P0 基础连接 19%**——SSH/SFTP/Serial/Telnet 主干全在插件轨上，这正是今晚 F1–F7 要补的。

## 2. 五个大类的口径

### P0 核心终端（100 条，66.8%）

`TERM / UI-TERM / KEY / UI-PANE / UI-TAB / UI-WIN / LOCAL / SESS`

不做就不是一个合格终端：PTY、渲染、键位、选择复制粘贴、查找、Tab、分屏、
窗口、主题基础、会话恢复。**全部必须做**，其中 45 条 partial 是“能用但还差边角”
（例如查找的高亮细节、主题的个别字段）。

### P0 基础连接（21 条，19.0%）

SSH 主干（建连/认证/known_hosts/别名历史）、Serial 主干（枚举/参数/读写/重连）、
Telnet 主干、SFTP 基础。

**必须做**，但目前是**最大的真缺口**：13 条 not_started 全在这里。
它们依赖 ACT-052 transport seam，所以顺序是“先接线，再上三个插件”。

### P1 工作区与设置（75 条，45.0%）

`UI-NAV / UI-PROF / UI-SET / UI-PLUG / NOTIFY / SEC / OPS / UI-SSH / THEME`

决定“好不好用”的完整体验：侧栏/工具栏/状态区、Profile 编辑、设置页、插件 UI、
通知、安全（插件不能读凭据）、连接诊断、主题。**应该做**，但可以分批：
今天已把侧栏壳、Profile 热键、Workspace、状态 pill 做掉，剩余是 Connection Manager、
设置页收尾、插件注入点。

### P2 高级连接（30 条，30.0%）

Proxy Command / X11 Forwarding / 持久转发 / Login Scripts / 算法配置、
串口 Hex 显示 / 换行转换 / 时间戳、Telnet Zmodem 协商。

**按需做**：面向的是“重度 SSH/嵌入式用户”，不是大众终端用户。
其中 10 条还是 needs_verification（上游字段都没核实），先别投入。

### P3 不建议/观察（18 条，25.0%）

| 条目 | 内容 | 建议 |
|---|---|---|
| PLUG-007..013 | 旧插件 Node sidecar + tabby-core/terminal/local shim + Angular WebView UI Host | **不做**：等于在 Rust 终端里再养一个 Electron 兼容层，和 v3 原生插件路线冲突；只保留“扫描并标记不兼容” |
| ZMODEM-001..004、UI-SER-008 | Zmodem 收发/文件选择/进度/断线处理 | **不做**：需要内建协议状态机 + 文件 UI，收益集中在极少数嵌入式用户；可留给第三方插件 |
| THEME-007 | 旧 Tabby CSS 主题转 Slint / WebView 适配 | **不做**：CSS 主题无法等价映射，做出来也是“看起来像” |
| UI-QUAKE-001..005 | Quake 模式（全局热键/停靠/自动隐藏） | **降级为 P2**：已有 3 条 implemented，剩下的是 Wayland 全局热键与边缘停靠，平台限制大 |
| PLAT-* | 平台相关（Windows/macOS 打包、Wayland 细节等） | **按目标平台决定**，不阻塞核心 |

> 注意：P3 里 5 条已经是 `unsupported`（ZMODEM×4 + WinSCP），
> 我们**没有装假实现**，这是之前就定好的口径。

## 3. 结论：三句话

1. **“未完成”不等于“必须做”**：51 条 not_started 里，13 条是 P0 连接主干（必须），
   15 条是 P1 体验（应该），8 条 P2 高级（按需），6 条 P3（建议不做）。
2. **真实完成度**：核心终端 66.8%，核心+体验 53.3%，全量 48.4%——
   对外说话用“核心 67%、整体 48%”，比单说 48.4% 更准确。
3. **最该投入的不是补 partial，而是补 P0 基础连接**：SSH/Serial/Telnet 一天不通，
   “终端 + 连接管理”的产品定位就立不住。

## 4. 建议的精简（如果目标是尽快发 0.6）

```text
保留  P0 全部（121 条）+ P1 的工作区/设置/通知/安全（约 60 条）
砍掉  P3 全部（18 条，其中 5 条已 unsupported）
延后  P2 高级连接（30 条）到 0.7
目标  精简后分母 ≈ 196 条，当前加权 53.3% → 补完 P0 连接后可到 ~75%
```
